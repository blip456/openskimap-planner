# OpenSki Planner for iOS (offline)

A native SwiftUI version of the beginner ski route planner. Everything runs on the phone:

- **Offline map**: the ski map (runs, lifts, lift stations) and the Protomaps basemap, served from PMTiles files in
  the app bundle through [MapLibre Native](https://maplibre.org/maplibre-native/ios/) (`pmtiles://file://…`).
- **3D terrain** (optional): the Mapterhorn elevation data, toggle with the **3D** button.
- **Routing**: a port of `planner/graph.mjs`, same options, same routes, same GPX export. Start, stops and
  destination; directions per leg; warnings; GPX export through the share sheet.
- **Search**: runs, lifts, villages, peaks and huts from the bundled planner data.
- **Saved routes**: name, folder, open, update, save as new and delete, stored on the phone (Application Support).
- **Map display**: runs, lifts, cross-country, touring & sled; colours by official difficulty or steepness; ski areas
  in colour; route arrows and distance markers. The choices are kept between launches.
- **No tile server**: the app reads the PMTiles files (ski runs and lifts, Protomaps basemap, Mapterhorn terrain)
  straight from the bundle. TileServer GL is only used by the web planner and gpx.studio; it is not needed on the phone.
- **No network**: the app never contacts a server. The data comes from the OpenSkiData download and Mapterhorn /
  Protomaps extracts that `npm run build` makes.

## Layout

```
ios/
  project.yml                   XcodeGen project (app target, SkiCore package, MapLibre package)
  Packages/SkiCore/             pure Swift core, no UIKit: builds and tests on macOS with `swift test`
    Sources/SkiCore/              port of planner/graph.mjs (network, routing, steps, GPX) + distance markers
    Sources/skicore-route/        command-line router, to compare the port with the JavaScript version
    Tests/SkiCoreTests/           routing, distance marker and option decoding tests
  OpenSkiPlanner/
    App/                          app entry point
    Map/MapCanvas.swift           MapLibre map (UIViewRepresentable): taps, camera, syncing the model to the map
    Map/MapLayers.swift           route, ski-area and visibility layers added to the bundled style
    Model/PlannerModel.swift      state: resort, route points, options, route, GPX, open saved route
    Model/SavedRoutes.swift       saved routes and their JSON store
    Model/DisplaySettings.swift   map display choices (UserDefaults)
    Support/                      offline data lookup, search index, labels and colours, formatting
    Views/                        map screen, Route / Saved / Map panels, route settings
    Views/Components/Glass.swift  Liquid Glass helpers (with a material fallback before iOS 26)
    Assets.xcassets               app icon
    Offline/                      generated by `npm run ios:export` (git-ignored)
```

`OpenSkiPlanner.xcodeproj` is generated from `project.yml` and not in git; run `xcodegen generate` after adding or
removing files.

## Build the offline data (once, on the Mac)

```bash
npm install
npm run build          # downloads OpenSkiData + Mapterhorn/Protomaps extracts, builds build/ (see the main README)
npm run ios:export     # copies the offline map, fonts, sprites and planner data into ios/OpenSkiPlanner/Offline
```

`ios:export` also rewrites the map styles so every URL points into the app bundle.

## Tests

```bash
cd ios/Packages/SkiCore
swift test                                   # unit tests (needs Xcode for XCTest)
swift run skicore-route ../../../build/planner/<resort>.json '[[lon,lat],[lon,lat]]'   # one route as JSON
```

To check the port against the web planner, run the same points through `skicore-route` and through
`SkiNetwork.route()` from `planner/graph.mjs`: distance, time, steps and track points should match.

## Build and run in the Simulator

Requirements: **full Xcode** (not only the Command Line Tools), `brew install xcodegen`.

```bash
cd ios
xcodegen generate                  # creates OpenSkiPlanner.xcodeproj (Swift packages are resolved by Xcode)
open OpenSkiPlanner.xcodeproj
```

Pick an iPhone simulator and press Run. From the terminal:

```bash
xcodebuild -project OpenSkiPlanner.xcodeproj -scheme OpenSkiPlanner \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

## Install on your iPhone (sideload from this Mac)

1. Connect the iPhone with a cable, unlock it and tap *Trust*. Enable **Settings → Privacy & Security → Developer
   Mode** on the phone (iOS 16+) and restart when asked.
2. In Xcode: **Settings → Accounts** → add your Apple ID (a free account is enough for your own device).
3. Select the **OpenSkiPlanner** target → *Signing & Capabilities* → tick *Automatically manage signing* and choose
   your team. Change the bundle identifier if Xcode reports it is taken (`local.openskimap.planner` by default).
4. Choose your iPhone as the run destination and press Run. On the phone, trust the developer app under
   **Settings → General → VPN & Device Management**.

With a free Apple ID the app expires after 7 days; rebuild from Xcode to refresh it.

## Limits and notes

- The map shows the resorts in `resorts.json` only (the same data as the web planner). Outside them the basemap
  is empty.
- The app loads the first resort in the export; several regions and downloading new ones are not built yet.
- Route points are set by tapping the map (every tap adds a point, like the web planner's *Plan route* mode).
  Pinch and drag still move the map; a quick double tap zooms instead of adding two points.
- Web-only features: saving routes to the project folder, Google Maps links, online geocoding, online base maps,
  TileServer GL tiles for gpx.studio, info cards with elevation profiles, the gradient profile chart, GPX download
  of a saved route or a whole folder.
- Always check the official piste map, signs and conditions on the day. OSM data can be incomplete.
